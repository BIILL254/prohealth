# Configure M-Pesa STK Push with Daraja

The ProHealth server already has an STK Push integration. It requests a Daraja access token, sends the payment prompt, stores the checkout request ID, and waits for the callback before marking an order paid. Keep Daraja credentials on the server; never place them in React code or commit them to Git.

## 1. Create sandbox credentials

1. Sign in or register at the [Safaricom Daraja Developer Portal](https://developer.safaricom.co.ke/).
2. Create a sandbox app and enable the M-PESA Express / STK Push product.
3. Copy that app's Consumer Key and Consumer Secret.
4. Use the sandbox shortcode and passkey listed by Daraja for its STK Push testing instructions. Do not use a production shortcode/passkey with sandbox credentials.

Safaricom describes sandbox apps as the place to simulate and test integrations before going live. The OAuth credentials are app-specific. See [Daraja](https://developer.safaricom.co.ke/) and Safaricom's [Getting Started documentation](https://developer.safaricom.co.ke/apis/GettingStarted).

## 2. Configure the server

From the project folder `C:\Users\bill7\Downloads\prohealth\prohealth`, copy the example environment file and edit it:

```powershell
Copy-Item server\.env.example server\.env
notepad server\.env
```

Set these values in `server/.env`:

```dotenv
MPESA_MODE=sandbox
MPESA_CONSUMER_KEY=your_sandbox_consumer_key
MPESA_CONSUMER_SECRET=your_sandbox_consumer_secret
MPESA_SHORTCODE=your_sandbox_shortcode
MPESA_PASSKEY=your_sandbox_passkey
MPESA_TRANSACTION_TYPE=CustomerPayBillOnline
MPESA_CALLBACK_URL=https://your-public-tunnel-host/api/mpesa/callback
```

For a PayBill, use `CustomerPayBillOnline`. For a Till / Buy Goods shortcode, use `CustomerBuyGoodsOnline` and the matching shortcode details provided for that merchant. The STK password is generated by the server from the shortcode, passkey and current Nairobi timestamp.

The callback URL must be publicly reachable over HTTPS by Safaricom. `localhost` and the Vite address on port 5173 are not reachable from Daraja. During local development, expose **port 3000** (the Express API) with a temporary HTTPS tunnel, then append `/api/mpesa/callback` to the tunnel's public URL. Update `MPESA_CALLBACK_URL` whenever the tunnel URL changes.

## 3. Run the app and test

Open two terminals in `C:\Users\bill7\Downloads\prohealth\prohealth`:

```powershell
npm run dev:server
```

```powershell
npm run dev:client
```

Open `http://localhost:5173`, sign in as a customer, create an order, and request M-Pesa payment using the sandbox test phone number specified by Daraja. The STK prompt or simulator should complete the flow and send its callback to the tunneled port 3000 endpoint. ProHealth only marks payment successful after a matching successful callback; the callback is matched against the checkout request ID, amount, phone and receipt.

`MPESA_MODE=simulate` is the local fake-payment mode and does not call Safaricom. Use `MPESA_MODE=sandbox` to exercise Daraja. Keep simulation enabled if the public HTTPS callback tunnel is unavailable.

## 4. Troubleshooting

- **OAuth failure:** verify the sandbox app's Consumer Key and Consumer Secret, and that `MPESA_MODE=sandbox`.
- **STK request rejected:** verify the app has STK Push enabled, the sandbox shortcode/passkey pair, phone format, transaction type, and that the amount is a positive whole number of KES.
- **Prompt appears but order stays pending:** confirm the callback URL is public HTTPS, points to port 3000, includes `/api/mpesa/callback`, and matches the current tunnel URL. Check the server terminal for a callback mismatch.
- **Credentials were exposed:** revoke or rotate them in Daraja and replace values in `server/.env`.

## 5. Go live only after sandbox verification

Production requires the merchant's approved live PayBill or Till details, production credentials, and a stable public HTTPS callback endpoint. Coordinate Daraja's Go Live steps with the business/shortcode owner. Then set `MPESA_MODE=live`, enter the production values, set the correct transaction type, and restart the API. Never test the live configuration with orders unless the merchant has explicitly approved real-money testing.

Safaricom's portal describes creating a sandbox app for testing and completing its Go Live process before using production credentials and a live shortcode: [Daraja Developer Portal](https://developer.safaricom.co.ke/).
